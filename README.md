# 听个响 · I Hear It

**你继续，俺在听**

**使用范围：目前需要配合 Kdenlive 工程使用，暂不支持其他剪辑软件，也不支持脱离工程、直接对独立音频文件进行完整检索。音频文件导入主要用于建立和校准样例库。**

「听个响」是一个可以用样本校准的声音检索与分类工具。

给几段声音当例子，说明想找什么、哪些容易认错，就能根据声音特征，从工程音轨里筛出相似片段。目标声音和分类方式，都由你的样例库决定。

不知道怎么描述某种声音也没关系：**“就找这样的。”给俺听一段，比解释半天管用。**

支持的能力包括：

- **自定义分类**：自由创建、命名和编辑分组，设置要找的声音与需要排除的声音，跟随样例库保存。
- **用样本校准**：既能提供“就找这样的”，也能补充“这种很像，但别算进去”，帮助区分目标与易混淆的声音。
- **建立和维护样例库**：通过引导试听、筛选候选，逐步收集样本；分组和样本可以随时增删、调整，保存后继续使用。
- **寻找相似声音**：按照样例库筛查音轨，提供候选片段和匹配参考，减少反复翻听的时间。
- **直观试听与取样**：查看波形、缩放局部、拖动选区，单击波形即可从该处试听；遇到典型声音，还能直接收进样例库。
- **衔接剪辑操作**：直接从 Kdenlive 工程音轨取样，确认后写入标记，或裁掉选中片段，保留后续片段原有的时间位置。

声音分析在本地完成。目标特征是否鲜明、样本是否有代表性，都会影响匹配效果；筛出来的候选片段，还需要你试听确认。

例如，可以用来寻找录音中的啧嘴、清嗓等杂音。你也可以围绕笑声、动物叫声、特定音效等声音建立样例库，在 Kdenlive 工程中尝试自己的检索任务。

**你来定什么声音值得找，剩下的，俺先听着。**

## 安装与启动

**便携版：** 解压完整文件夹，双击 **ihearit.exe**。无需安装 Node.js、Python 或 npm 依赖。

**源码版：** 下载源码或克隆仓库后，双击 **setup-and-start.bat**。首次需要网络，脚本会准备 Node.js 24.13.0、按锁文件安装依赖、生成启动器并打开软件。已有同版本 Node.js 时直接复用，否则下载经过 SHA-256 校验的便携运行环境。文件保存在工程目录，不修改系统设置，不需要管理员权限。

准备完成后，使用 `ihearit.exe` 或 `start.cmd` 即可启动。安装失败会保留提示，可检查网络后重新运行 BAT。

声音解码使用已安装的 **Kdenlive/FFmpeg**。如果没有自动找到，在“工具与设置 → 选择解码器”中选择 `ffmpeg.exe`，同目录需有 `ffprobe.exe` 及配套文件。发布包不包含 Kdenlive 或 FFmpeg。

## 开始使用

1. 选择 `.kdenlive` 工程，再选择序列和音轨。
2. 点击“新建库”，设置声音分组，通过引导筛查、试听和归组收集样本；也可以直接导入音频取样。
3. 为分组设置“要处理”或“用于排除”，提供典型目标样本，以及容易混淆的排除样本。
4. 开始扫描，逐条试听候选。可在波形上缩放、拖选；单击波形从该位置试听。
5. 确认后标记、保存样本，或核对选区后执行裁切。裁切会留下等长空白，后续片段保持原有时间位置。

标记类别可以自行选择。第一次点击新候选的裁切按钮会先选中并显示范围，核对、试听后再次点击执行。

修改工程前，请先保存 Kdenlive 中未保存的内容；工具写入后重新加载工程。每次写入会自动备份，支持撤销工具自身的修改。

## 样例库与采样

分组名称、用途和样本跟随样例库保存，可以随时编辑。使用“声音校准 / 采样”导入音频取样，也可以直接在候选旁点击“采样”，或在主界面点击“保存至样本库”。

采样窗口提供全局概览、局部缩放、位置导航、选区和播放进度线。滚轮缩放，Shift 拖动平移，拖动选区两端调整范围；精确起止时间可选填。单个样本长度为 0.02～10 秒，不能跨越工程中的剪辑或空白。

增加样本后可“重新筛选”；工程或素材修改后使用“强制重新采样”。换人、设备或录音环境后，建议补充相应样本进行校准。

## 支持范围

- 当前主要支持 Windows x64，检索和工程操作面向 Kdenlive。
- 分析工程引用素材的原始音频，不渲染 Kdenlive 的实时混音和效果。
- 嵌套序列、变速、交叉混合、跨剪辑裁切及未支持的片段效果会被明确拒绝。
- 自动结果可能误检或漏检，相似度不代表准确率，候选需要人工试听确认。

## 数据与隐私

声音分析在本地完成，后台仅监听本机地址 `127.0.0.1`。设置、样例库和缓存保存在程序目录的 `data` 中；样例库保存特征与标签，不保存原始录音。

仓库和通用发布包不包含用户的录音、工程、样例库、缓存或诊断日志。npm 依赖和 Node.js 运行环境不提交到源码仓库，由锁文件和一键脚本准备；便携版包含运行所需的文件。

## 开发与打包

开发环境需要 Node.js 22 或以上，以及 FFmpeg/ffprobe；一键脚本和自动发布使用 Node.js 24.13.0。FFmpeg 可通过 PATH 或 `KDENLIVE_FFMPEG` 指定。

```text
npm ci --ignore-scripts --omit=dev
node tools/compile-launcher.js
npm test
npm start
```

界面使用原生 HTML/CSS/JavaScript，后台使用 Node.js 与工作线程。YAMNet 提取声音特征，结合自定义信号分析和目标/排除样本匹配进行筛查。两个直接 npm 依赖为 `@xmldom/xmldom` 与 `onnxruntime-node`，版本由 `package-lock.json` 固定。

打包与校验：

```text
npm run build:win
npm run build:source
npm run verify:release
```

输出位于 `dist`。推送与 `package.json` 版本一致的 `v版本` 标签后，GitHub Actions 会运行检查、构建并发布通用包。更新说明见 [CHANGELOG.md](CHANGELOG.md)。
