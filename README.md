# 听个响 · I Hear It

**你继续，俺在听**

**使用范围：目前需要配合 Kdenlive 工程使用，暂不支持其他剪辑软件，也不支持脱离工程、直接对独立音频文件进行完整检索。音频文件导入主要用于建立和校准样例库。**

「听个响」是一个可以用样本校准的声音检索与分类工具。

给几段声音当例子，说明想找什么、哪些容易认错，就能根据声音特征，从工程音轨里筛出相似片段。目标声音和分类方式，都由你的样例库决定。

不知道怎么描述某种声音也没关系：**“就找这样的。”给俺听一段，比解释半天管用。**

支持的能力包括：

- **自定义分类**：自由创建、命名和编辑分组，设置要找的声音与需要排除的声音，跟随样例库保存。
- **用样本校准**：既能提供“就找这样的”，也能补充“这种很像，但别算进去”，帮助区分目标与易混淆的声音。
- **建立和维护样例库**：通过引导试听、筛选候选，逐步收集样本；分组和样本可以随时增删、调整，保存后继续使用。
- **寻找相似声音**：按照样例库筛查音轨，提供候选片段和匹配参考，减少反复翻听的时间。
- **直观试听与取样**：查看波形、缩放局部、拖动选区，单击波形即可从该处试听；遇到典型声音，还能直接收进样例库。
- **衔接剪辑操作**：直接从 Kdenlive 工程音轨取样，确认后写入标记，或裁掉选中片段，保留后续片段原有的时间位置。

声音分析在本地完成。目标特征是否鲜明、样本是否有代表性，都会影响匹配效果；筛出来的候选片段，还需要你试听确认。

比如，最初的用法是寻找录音中的啧嘴、清嗓等杂音。你也可以围绕笑声、动物叫声、特定音效等声音建立样例库，在 Kdenlive 工程中尝试自己的检索任务。

**你来定什么声音值得找，剩下的，俺先听着。**

## 名称与文件

中文名称：**听个响**。英文名称：**I Hear It**。开发标识（仓库建议名、package 名称）：`ihearit`。

Windows 主启动器为 `ihearit.exe`，英文启动脚本为 `start.cmd`；完整包使用 `ihearit-v版本-win-x64.zip`，个人包追加 `-personal`，补丁和源码分别追加 `-patch`、`-source`。中文界面与副标题保持不变。保留原有中文启动脚本，主程序统一为 ihearit.exe；`data`、样例库、缓存和工程历史的存储方式保持兼容。

## 从源码一键启动

Windows x64 用户可以双击 **setup-and-start.bat**：准备 Node.js 24.13.0（已有同版本时复用，否则下载校验后的便携运行环境）、按锁文件安装依赖、生成启动器并打开软件。首次需要网络；下载和依赖均留在工程目录，不修改系统设置，不需要管理员权限。安装完成后可直接使用 `ihearit.exe` 或 `start.cmd`。失败时会保留提示，重新运行即可重试。

仓库不提交 npm 依赖或 Node.js 运行环境；`package-lock.json` 固定安装版本。便携完整包自带运行文件，无需使用该 BAT。FFmpeg 仍由已安装的 Kdenlive 或独立安装提供。

## 使用

1. 解压完整文件夹，双击 **ihearit.exe**，直接打开界面，没有黑色命令窗口。“start.cmd”和原来的“启动助手.cmd”也会转交给这个启动器。启动器只是用 Windows 自带 .NET 启动隐藏的 Node，分析、筛选和工程编辑仍由 JavaScript 实现，不增加 npm 依赖。
2. 选择 `.kdenlive` 工程、序列和音轨。若未找到解码器，在右上角“工具与设置”中点击“选择解码器”，选 Kdenlive/bin/ffmpeg.exe；同目录需有 ffprobe.exe 和其配套运行文件。
3. 通用版从空白库开始。个人包可在本地打包时选择自己的样例库，不会上传到公开发布。“新建库”会引导你命名、设置分组、选择音源、初步筛查、逐条试听归组，最后生成个人库。建议先筛查30～120秒，也可调整起止时间。未归组的候选不会保存；取消引导不会修改当前库。也支持仅创建空白库后手动采样。
4. 分组随库保存，可自行命名并设置为“要处理”或“用于排除”，选择短促声音、较长声音或两类声音；“常见口腔声分组”仅是可选模板。顶部计数、快捷归组按钮、分类下拉框和采样类型均来自当前库。底部显示前三组快捷键1～3，其余组可用下拉框选择。“编辑库”支持增删改名、调整用途、查看或删除单个样本、在兼容分组间移动样本；删除带样本的组须再次确认。分组改名影响后续标记，不改写工程中已有的标记。
5. 点击“开始扫描 / 读取缓存”。默认类别 6。换个人库后，确认记录按库隔离。新样例可用“重新筛选”更新结果，不需要重新解码；工程或素材修改后可“强制重新采样”。
6. 每行可试听、标记或裁切。第一次点击新行的裁切只选择并显示范围，调整、试听后再点击执行。裁切留等长空白，后续片段不移动；保留已验证的静态限幅器，并按需要分离目标音频的组合关系。
7. 每次修改工程前自动备份到工程旁 `.noise-assistant-history-js`，支持多步撤销。先在 Kdenlive 保存未保存的修改，助手写入后再重新加载。JS 版只撤销自身的修改，不接管 Python 版的历史。
8. 关闭最后一个助手窗口后约1.5秒，后台会取消扫描、停止本工具启动的音频读取与文件选择窗口，并等当前工程写入和撤销记录收尾后退出。刷新窗口或关闭多个助手窗口中的一个不会退出；缩到后台时连接保持。也可用 **工具与设置 → 退出听个响** 主动结束，包括正在扫描时。

“声音校准 / 采样”可继续给已有库补充样本：从工程音轨取样或导入录音，显示波形、拖选、试听并选择库内分组。单个样本支持0.02～10秒，不能跨空白或剪辑边界。

## 旧版样例与缓存

“读取个人库”支持导入 Python 版的 `.npz`，由 JavaScript 直接解析；保存为 JSON 特征库，不需要 Python，也不覆盖原 NPZ。个人完整包已经转换随附的原样例库。另一台电脑后来新增的样例，可直接导入那台电脑上的最新版 NPZ。

开发期 JS v3.x 的 JSON 库自动迁移：保留库标识和全部特征，将原来的类型写入库内分组。第一次覆盖保存旧 JSON 前，会在旁边保留 `.pre-v4.bak` 原文件。带自定义分组的格式由当前 1.0 正式版兼容读取；工程和素材未改动时可继续复用分析缓存。新版本的打包文件不覆盖 `data`。

缓存与设置保存在程序目录 `data`，与 Python 版分开。旧的整轨分析缓存不迁移，首次使用 JS 版需要扫描一次；之后复用 JS 缓存。样例库只保存特征和标签，不保存原始录音。导出诊断日志包含运行信息、步骤耗时与错误，不含媒体或特征向量。

## 技术与依赖

- Node.js 内置模块处理 HTTP、工作线程、文件读写、压缩、日志、旧 NPZ/NPY 和 WAV 编码。
- 使用同源、带会话令牌的 EventSource 长连接跟随界面生命周期；关闭连接有短暂重连宽限。后台先协作取消任务再退出，避免中断工程备份和写入；不靠后台页面定时器判断存活，不终止系统浏览器的共享进程。
- 自实现能量包络、FFT、峰值/宽度筛选及相似度匹配，与原 Python 特征计算交叉验证。
- 两个固定版本直接依赖：`@xmldom/xmldom@0.9.12` 和 `onnxruntime-node@1.31.1`。
- ONNX 的安装工具引入一些间接依赖；开发安装共 18 个包。最终 Windows 运行包只保留 XML、ONNX Node 和 ONNX Common 三个运行包，剔除安装辅助库与其他平台的二进制文件。
- 便携完整包是裁剪后的运行文件集合，不需要 npm 安装；开发、`npm ls` 或依赖审计请使用源码包并执行 `npm ci`，以恢复锁定的完整开发安装树。
- `package-lock.json` 锁定完整依赖树；`.npmrc` 禁用安装脚本，避免自动下载 GPU 组件。没有开发依赖，没有 npm 远程脚本，没有 CDN。
- YAMNet 在本机 CPU 运行；程序初始化模型前以进程环境变量关闭 ONNX Runtime 遥测。后台只监听 `127.0.0.1`，接口使用随机会话令牌和同源限制。

开发环境需要 Node 22 或以上：

```text
npm ci --ignore-scripts --omit=dev
npm test
node server.js
```

后台测试（不打开窗口、不播放声音）：`node server.js --no-open`。测试可能需要允许本机回环网络连接。

打包 Windows x64 完整版：

```text
node tools/build.js
node tools/build.js --profile="旧版个人库.npz"
```

输出在 `dist`。构建时用系统自带 C# 编译器生成小型 GUI 启动器；无需下载构建包。打包不修改个人库或原工程。Node 运行环境来自执行打包的 Node，构建时需为 Windows x64。

## 当前边界

分析的是工程引用的素材原音，不渲染 Kdenlive 实时混音和效果。嵌套序列、变速、交叉混合、跨剪辑裁切和未支持的片段效果会明确拒绝。时间线标记写入所选序列的 Guide 数据。自动结果可能误检或漏检，相似度不是准确率；换人/设备/录音环境时需要校准。当前主要验证 Windows x64。

本项目保留 `models/LICENSE`、`models/NOTICE.md` 与 `licenses/Node-LICENSE.txt`，运行包中保留各第三方模块许可。模型来源见 `models/NOTICE.md`。应用自身源码使用 [MIT 许可证](LICENSE)。模型、运行库与其包含的组件保留各自许可证，详见 [第三方声明](THIRD_PARTY_NOTICES.md)。

布局检查：`node tools/layout-check.js` 使用独立的无界面 Edge，检查窗口适配和按钮可见性，不打开桌面窗口或播放声音；无需增加 npm 依赖。

更新记录见 [CHANGELOG.md](CHANGELOG.md)。

## 下载与发布

正式版本从 [GitHub Releases](https://github.com/Fantasy-Dm/ihearit/releases) 下载。公开发布仅包含通用 Windows x64 完整包、通用源码包和 SHA-256 校验文件；不包含个人样例库、录音、缓存、工程或诊断日志。

当前正式版本从 **1.0.0** 开始编号。修改 `package.json` 中的版本，推送对应 `v版本` 标签后，GitHub Actions 会在 Windows 上安装锁定依赖、运行测试、打包并发布。标签与应用版本不一致时拒绝发布。应用版本与样例库内部格式版本相互独立。

源码开发先执行 `npm ci --ignore-scripts --omit=dev`，再执行 `node tools/compile-launcher.js` 和 `npm test`。测试需要 FFmpeg 与 ffprobe 位于 PATH，或通过 `KDENLIVE_FFMPEG` 指定 FFmpeg 路径。普通用户使用完整包即可。
